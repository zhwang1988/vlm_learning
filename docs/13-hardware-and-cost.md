# 13 · 算力选型与成本（Day 0 必读）

> 这一篇解决一个问题：**我该租什么卡、在哪租、怎么租最省、租完怎么立刻开始。**
>
> 价格是 2026-09 的快照，云 GPU 价格变动极快，**下单前请以平台实时价为准**。
> 但选型逻辑（该买什么规格、什么计费方式、哪些坑）不会变。

## 一、先算清楚：你到底需要什么

不要先选平台，先确认需求。这个项目的算力需求分成三段，**每段要的东西完全不同**：

| 阶段 | 周次 | 真正需要什么 | 显存底线 |
| --- | --- | --- | --- |
| **A. 学架构 + 数据工程** | W1–W2 | 几乎不需要 GPU。跑通一次推理 + 读懂代码 | 12 GB 就够（甚至用 API） |
| **B. 训练（重头）** | W3–W5 | 3B/7B QLoRA SFT + DPO | 24 GB 够 3B QLoRA；7B QLoRA 要 24 GB 且压短序列 |
| **C. 部署 + Agent + 产品** | W6–W8 | 常驻推理服务（vLLM）+ 开发环境 | 24 GB 舒服；32 GB 更省心 |

**关键结论：你 80% 的时间在 W1–W2 和 W6–W8，而这两段其实都不需要大卡。**

真正吃卡的是中间那 3 周。所以策略是：

> **租一张 24 GB 的卡，按秒计费，用完就关。**
> 不要一上来就买包月 A100 —— 那是最常见的浪费。

### 显存需求速查（QLoRA，batch=1，序列 2048）

| 模型 | 训练方式 | 权重 | +优化器/激活 | 实际占用 | 24 GB 能否 |
| --- | --- | --- | --- | --- | --- |
| Qwen2.5-VL-3B | QLoRA 4bit | ~2 GB | +8~10 GB | **~12 GB** | ✅ 很宽松 |
| Qwen2.5-VL-3B | LoRA bf16 | ~6 GB | +10~12 GB | **~18 GB** | ✅ 可以 |
| Qwen2.5-VL-3B | 全参 bf16 | 6 GB | +30 GB | ~36 GB+ | ❌ 需 80 GB |
| Qwen2.5-VL-7B | QLoRA 4bit | ~5 GB | +12~16 GB | **~20 GB** | ✅ 压短序列可以 |
| Qwen2.5-VL-7B | LoRA bf16 | ~15 GB | +18 GB | ~33 GB | ❌ 需 80 GB |
| Qwen2.5-VL-3B | vLLM 推理 bf16 | ~7 GB | + KV cache | **~12–16 GB** | ✅ |

用 `python scripts/estimate_vram.py --model 3b --method qlora` 可以自己算。

> 视觉模型比纯文本模型显存高，因为**图像 token 很贵**：一张 1024×1024 的图
> 经过 patch=14 + 2×2 merge 之后 ≈ 1332 个 token，相当于 1300 字的 prompt。
> 详见 `docs/04-qwen25vl.md`。所以 `max_pixels` 是比 `batch_size` 更有效的省显存旋钮。

## 三、我的建议（直接照抄）

### 方案：AutoDL 按量 + 无卡模式（预算 ≈ ¥300 搞定 8 周）

```
主平台：   AutoDL
卡型：     RTX 4090 / 24GB         ¥1.88 / 小时（按秒计费）
备选卡：   RTX 5090 / 32GB         ¥2.78 / 小时（显存多 8G，省心）
降级：     RTX 3090 / 24GB         ¥1.32 / 小时（慢一点，便宜 30%）
镜像：     PyTorch 2.x + CUDA 12.x + Ubuntu 22.04（选官方基础镜像）
系统盘：   50 GB
数据盘：   100 GB（模型 + 数据集 + checkpoint，关机不丢）
认证：     ⭐ 做学生认证 → 会员折扣 + 算力券；没有学生身份也会有新用户礼包
充值：     先充 ¥50 试水（≈ 25 小时 4090），确认好用再充 ¥300
```

### 为什么是它

1. **¥1.88/h 按秒计费** —— 你随手开 20 分钟跑个推理，只扣 ¥0.6，不是扣 1 小时。
2. **无卡模式 ¥0.1/h** —— 这是最被低估的功能。写代码、传数据、装环境、
   读代码这些事**完全不需要 GPU**，但很多人开着 4090 在做这些事，钱全烧在等待里。
   正确姿势：**无卡模式开发 → 切换 GPU 模式训练 → 训练完立刻关机**。
3. **环境开箱即用** —— 预装 CUDA + PyTorch + JupyterLab，省掉最容易翻车的 3 小时。
4. **文档/社区最全** —— 你第 1 周是新手，遇到问题能搜到中文答案，这个价值远超 ¥0.2/h 差价。

### 什么时候升级

| 触发条件 | 动作 |
| --- | --- |
| 晚高峰抢不到 4090 | 切 **恒源云**（同样价格，A100 池子更足）；或凌晨跑训练 |
| 要跑 7B LoRA bf16 或 3B 全参 | 升 **A800-80G ¥4.98/h**（AutoDL 有升降配置功能，不用重建实例）|
| 要跑 3 天以上的长训练 | 用平台的**竞价/闲时实例**，能省 40–60%，但**必须开 checkpoint 续跑** |
| 要给 Shopify 挂 7×24 常驻服务 | **不要**用按量 GPU 顶着（24×7×8 周 ≈ ¥2500）。改用推理 API（见下） |

### 关于 W6–W8 的常驻推理成本 —— 这是唯一的大坑

你的 Shopify App 需要一个**随时在线**的模型服务。如果租着 4090 让它 7×24 开着，
8 周要烧 ~¥2500，比前面所有训练加起来贵 10 倍。

**三个正确的做法（按推荐度排序）：**

1. **训练用 GPU，推理用 API**（最推荐）
   把后训练好的 LoRA 权重合并，部署到**按 token 计费的推理服务**
   （硅基流动、阿里云百炼、火山方舟等）。没有请求时成本为 0。
   这个项目是 demo 性质，一天可能就几百次调用，**一个月几块钱**。

2. **Serverless GPU**（RunPod Serverless / 各家的函数式 GPU）
   冷启动几秒，按秒计费，无请求自动缩容到 0。

3. **演示时开、平时关**
   需要录屏/给客户看的时候启动 4090，演示完关机。配合 `scripts/demo_up.sh`。
   **绝对不要**为了"随时能访问"而让它空转 —— 空转的 GPU 和训练的 GPU 一个价。

## 四、租完立刻开始：一条命令

登录实例后（JupyterLab 的 Terminal 或 SSH 都行），只需要跑这一条：

```bash
cd /root && git clone <你的仓库地址> multimodal-lab && cd multimodal-lab && bash scripts/cloud_bootstrap.sh
```

如果你还没推到 git，先把仓库传上去（见第五节），或者直接手动跑：

```bash
bash scripts/cloud_bootstrap.sh --skip-clone
```

`scripts/cloud_bootstrap.sh` 会依次做这些事，并且**每一步都会检查、失败会告诉你怎么修**：

1. 打印机器信息（GPU 型号、显存、CUDA、磁盘），让你确认没租错卡
2. 建独立虚拟环境（不污染系统 Python）
3. 配 **HuggingFace 国内镜像**（`hf-mirror.com`）—— 不配这一步下载模型会卡到绝望
4. 装依赖（按阶段分三档，只装你现在需要的）
5. 下载 Qwen2.5-VL-3B-Instruct（~7 GB，走 ModelScope 或镜像）
6. 跑一个 **smoke test**：让模型看一张图并回答问题，把答案打印出来
7. 打印 GPU 显存占用，告诉你实际能开多大 batch

跑完你会看到：

```
[✓] GPU  : NVIDIA GeForce RTX 4090 (24 GB)
[✓] 依赖 : transformers 4.49.x, peft 0.13.x, torch 2.x+cu12x
[✓] 模型 : Qwen/Qwen2.5-VL-3B-Instruct  (6.9 GB, 已缓存)
[✓] 冒烟 : 模型回答 -> "图片里有一只橘色的猫，坐在白色的沙发上。"
[✓] 显存 : 峰值 7.8 GB / 24.0 GB  → 训练可用 batch size ≈ 2（QLoRA, seq 2048）
     下一步: python -m src.minivlm.processor      # Day 4 的验收测试
```

**跑通这条命令 ≈ Day 1 就完成了。**

## 五之二、本地做什么，云上做什么（省钱的核心）

云 GPU 按时计费，**在云上写文档、读讲义、调纯 Python 逻辑 = 纯烧钱**。
所以分工要划清楚。下面这张表是**实测结果**（在 Mac 上逐个模块跑出来的，不是猜的）：

| 模块 | 本地能跑吗 | 说明 |
| --- | --- | --- |
| `src.eval/` 的 `metrics` `judge` `hallucination` `agent_eval` | ✅ **零依赖** | 评测逻辑纯 Python，本机直接跑 |
| `src.shopify/` 全部（`auth` `webhooks` `billing` `client`） | ✅ **零依赖** | 认证/幂等/计费/GraphQL 都是纯逻辑 |
| `src.data/` 全部 | ✅ 只需 `numpy` | 图像处理、去重、打包 |
| `src.agent/`（`tools` `retriever` `agent`） | ✅ 只需 `numpy` | 工具调用、检索、主循环 |
| `src.minivlm/` 全部 | ❌ 需 `torch` | 真实张量计算，必须上云 |
| `src.train/` 全部 | ❌ 需 `torch` | LoRA / DPO / VRAM 估算 |

**结论：W4（评测）和 W7（Shopify）这两周的代码，你在本地就能写完并调通，不用开机。**
只要本地装一个 numpy（几十米的东西，不用 CUDA）：

```bash
pip install numpy        # 解锁 src/data 和 src/agent 的自检
```

其余的分工：

| 事情 | 在哪做 | 为什么 |
| --- | --- | --- |
| 读 `docs/*.md`、写笔记、复盘 | **本地** | 不碰 GPU，零成本 |
| 改代码、写新函数 | **本地** | 编辑器体验更好，云上 JupyterLab 不适合长时间写码 |
| 跑纯 Python 自检 | **本地** | 见上表 |
| 跑 `scripts/env_check.py` | **两边都跑** | 同一个脚本，自动区分模式，见下 |
| 跑 `scripts/estimate_vram.py` | **本地** | 纯数学，用来决定租什么卡 —— 得在租之前跑 |
| 真实推理（notebook / `src/minivlm/generate.py`） | **云上** | 要 CUDA 和显存 |
| 数据合成、清洗、训练、评测、vLLM | **云上** | 要算力，且数据在数据盘上 |

### `env_check.py` 为什么两边都能跑

它自己判断环境：**检测到 CUDA → 按云训练机检查；否则 → 按本地开发机检查**。

区别在「及格线」：同一个「没装 torch」，

- 在**本地**只是 `[!]` 提示（你的工作是读文档改代码，本来就不需要）
- 在**云上**是 `[X]` 硬伤（没 torch 什么都干不了）

```bash
# 本地：只想知道仓库结构对不对
python scripts/env_check.py

# 云上：真正的上车前门禁
python scripts/env_check.py --mode cloud

# 只看一行结论 / 给 CI 用
python scripts/env_check.py --quiet      # mode=local fail=0 warn=17
python scripts/env_check.py --json
```

退出码 `0` = 没有必须修复项，`1` = 有。本地模式退出码是 0，
所以可以放心把 `make check` 挂进任何本地脚本而不会被阻塞。

> 判据很简单：**只要你不打算现在开训，就在本地跑；准备开训了，在云机器上再跑一遍 `--mode cloud`。**

## 六、七个必踩的坑（提前给你打预防针）

1. **🔴 忘了关机** —— 按秒计费不等于免费。养成习惯：`python train.py && /usr/bin/shutdown`，
   训练完自动关机。AutoDL 支持这个，其他平台多数也支持。**这一个习惯能省你一半的钱。**

2. **🔴 在训练环境里 `pip install vllm`** —— vLLM 会拉一套自己的 torch，
   把训练环境的 torch 换掉，然后你就 CUDA mismatch 了。
   **永远为 vLLM 单独建一个环境**（`scripts/cloud_bootstrap.sh --with-vllm` 会建独立 venv）。

3. **🔴 数据只在云上** —— 平台跑路、实例被回收、误删数据盘，都会让你 8 周白干。
   **checkpoint 和 `data/processed/` 一定要定期拉回本地。**
   `bash scripts/sync_down.sh` 干这个（Day 18 会用）。

4. **🟡 依赖平台"总是有卡"** —— 晚 8 点到凌晨 2 点是高峰，4090 经常抢不到。
   提前**克隆一个实例备用**，或者接受"错峰训练"（凌晨跑其实更快也更便宜）。

5. **🟡 选了 Miniconda 基础镜像** —— 然后花 3 小时调 CUDA 版本。
   **选 PyTorch 镜像，不要选 Miniconda 基础镜像。**

6. **🟡 系统盘开太小** —— 镜像本身占几十 GB，模型十几 GB，数据集几十 GB。
   系统盘至少 50 GB，或者把东西都放数据盘。

7. **🟡 用 fp16 在 T4 上跑 bf16 配置** —— T4（16 GB）不支持 bf16。
   如果临时用了 T4：`bf16=False, fp16=True`，并且 `max_length` 压到 1024。
