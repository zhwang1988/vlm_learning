# 08 · 评测体系

> 对应 Day 19–Day 24
>
> **这是整个 8 周里最重要的一周。** 没有评测的调优是玄学；有了评测，后面每一步都有方向。

## 概念

### 三层评测

```
第一层 · 通用榜单        证明「模型没退化」
  MMMU / MMBench / OCRBench / POPE ...
  作用：横向对比、发现灾难性遗忘
  局限：和你的业务几乎无关

第二层 · 领域评测集      证明「模型变好了」   ← 本项目的核心资产
  自建电商客服图文评测集，300–500 条
  作用：指导每一次训练决策

第三层 · 端到端业务指标  证明「产品有用」
  任务成功率 / 转人工率 / 首次解决率 / 用户满意度
  作用：决定上线与否
```

**最常见的错误是只做第一层**。榜上高 2 分，业务上一问三不知。

### 通用榜单速查

| 榜单 | 测什么 | 为什么重要 |
|---|---|---|
| **MMMU** | 大学水平多学科图文推理 | 综合难度标杆，天花板指标 |
| **MMBench** | 20 类细粒度能力 | 覆盖面广，诊断性强 |
| **MMVet** | 综合能力，GPT-4 打分 | 主观质量 |
| **OCRBench** | OCR 综合 | **电商关键**：尺码表、吊牌、快递单 |
| **DocVQA** | 文档问答 | 详情页理解 |
| **ChartQA** | 图表理解 | 销售数据、尺码对照表 |
| **POPE** | 物体存在性幻觉 | **幻觉检测标准** |
| **HallusionBench** | 复杂幻觉 + 视觉依赖 | 检测「不看图瞎答」 |
| **RealWorldQA** | 真实场景空间理解 | 日常图像 |
| **MathVista** | 数学图文推理 | 复杂推理 |
| **CCBench / MMBench-CN** | 中文能力 | **中文场景必看** |
| **MMStar** | 抗数据泄露的纯净集 | 检验是否真的涨了 |

**特别推荐 MMStar**：它剔除了训练数据里出现过的样本，能区分「真涨」和「背题」。

### 通用榜单为什么不能代表业务

三个具体原因：

1. **分布不同**：MMMU 考的是教科书插图、科学图表；你的业务是手机拍的商品瑕疵照——分辨率低、光线差、构图乱。
2. **任务不同**：榜单答案是选择题；你要的是多轮对话 + 主动澄清 + 情绪安抚。
3. **成功标准不同**：榜单答对 60% 算不错；客服答错一次可能导致退货，**代价不对称**。

所以你必须自建领域评测集。

### 领域评测集的构建原则

**原则 1：来自真实分布，不是想出来的**

错误做法：自己想 50 个问题。
正确做法：去真实客服记录/问答区抄 300 个真实问题，再从中选 300 条。

**原则 2：四层难度**

| 难度 | 定义 | 占比 | 例子 |
|---|---|---|---|
| L1 单图单事实 | 图里直接能看到 | 30% | 「这个是什么颜色」 |
| L2 单图推理 | 需要结合常识判断 | 35% | 「这个线头算质量问题吗」 |
| L3 多图/图+文冲突 | 需要对比或多信息源 | 25% | 「你发的和我收到的怎么不一样」 |
| L4 模糊/需澄清/应拒答 | 信息不足 | 10% | 「这个好看吗」「我穿 S 行不行」（没说身高体重） |

**L4 最能区分模型好坏**。基座模型在这里几乎必错（会硬答），好的微调模型会说「方便告诉我您的身高体重吗」。**这一层是 SFT 数据质量的直接体现。**

**原则 3：答案形态要可比**

给定性答案，没法自动评分。解法是**双轨制**：

- **可判定的**：意图分类、要素抽取、是否拒答、是否引用图片证据 → 规则精确匹配
- **不可判定的**：语气、帮助性、事实准确性 → LLM judge

**原则 4：防泄漏**

必须做 pHash 交叉检查：评测集里的图片，**不能**出现在训练集里。否则你测的是记忆能力。

```python
train_hashes = {phash(img) for img in train_images}
for s in eval_set:
    assert min_hamming(phash(s.image), train_hashes) > 8, "leakage!"
```

### LLM-as-judge 的四个偏见与对策

| 偏见 | 表现 | 对策 |
|---|---|---|
| **位置偏见** | 偏爱第一个答案 | 交换顺序各评一次，取平均 |
| **长度偏见** | 偏爱更长的答案 | prompt 里明确说明「长度不代表质量」 |
| **自我偏好** | 偏爱自己生成的答案 | judge 用与 policy 不同的模型 |
| **格式偏见** | 偏爱 markdown 结构化的答案 | 明确要求「忽略格式，只看内容」 |

**校准方法**：让 judge 给 50 条样本打分，你自己也打一遍，算 **Spearman 相关系数**。低于 0.6 说明 judge prompt 需要重写。目标 ≥ 0.7。

**Judge prompt 模板**（Day 21 用）：

```
你是电商客服质量评审员。给定【用户问题】【图片描述】【客服回复】【参考答案】，
从三个维度打分（1-5）：

1. 事实准确性：回复是否与图片和商品信息一致？有无编造？
2. 有用性：用户的问题是否被解决？是否需要澄清时主动澄清了？
3. 语气：是否专业、有同理心？（忽略长度和格式，长不等于好）

输出 JSON: {"accuracy": n, "helpfulness": n, "tone": n, "reason": "..."}
```

### 幻觉的三种类型

| 类型 | 例子 | 成因 | 检测方法 |
|---|---|---|---|
| **存在性幻觉** | 图里没有口袋，模型说有 | 语言先验压过视觉证据 | POPE 式：问不存在的东西 |
| **属性幻觉** | 图里是深蓝，模型说藏青 | 细粒度视觉分辨不足 | 颜色/材质/数字抽取对比 |
| **关系幻觉** | 说「左边的模特穿着它」，其实图里没人 | 空间关系建模弱 | 空间关系问答 |

**存在性幻觉最严重也最容易测**。构造方法：拿一张商品图，问 10 个「图里有没有 X」的问题，其中 5 个 X 不存在。模型回答「有」的比例就是幻觉率。

**缓解幻觉的四招**（Day 22 要实验对比）：

1. **Prompt 约束**：明确要求「只基于图片可见内容回答，不确定就说不确定」
2. **引用证据**：要求模型先描述「我在图中看到的」，再回答
3. **拒答训练数据**：SFT 数据里加入 8% 的拒答样本
4. **contrastive DPO**：用「同答不同图」的偏好对（见 `07-alignment.md`）

**预期效果排序**（大致）：3 > 4 > 1 > 2。但 1 和 2 是零成本的，先试。

## 工程细节

### 评测报告应该长什么样

```markdown
# Eval Report v1

## 配置
- 基座: Qwen2.5-VL-3B-Instruct
- 微调: LoRA r=16, lr=1e-4, 3 epochs, 8k 样本
- max_pixels: 1280*28*28
- 评测集: cx_eval_v1 (n=320, L1=96/L2=112/L3=80/L4=32)

## 领域评测

| 指标 | Base | +SFT | Δ |
|---|---|---|---|
| 意图分类准确率 | 71.2 | 88.4 | +17.2 |
| 图片问题准确率 | 54.6 | 71.3 | +16.7 |
| 拒答正确率 (L4) | 18.8 | 66.2 | +47.4 |
| 格式合规率 | 82.1 | 97.5 | +15.4 |
| 幻觉率 (POPE式) | 23.4 | 11.2 | -12.2 |
| LLM-judge 综合 | 3.12 | 4.05 | +0.93 |

### 分层
| 难度 | Base | +SFT | Δ |
|---|---|---|---|
| L1 | 82.3 | 91.7 | +9.4 |
| L2 | 58.9 | 74.1 | +15.2 |
| L3 | 41.2 | 62.5 | +21.3 |
| L4 | 18.8 | 66.2 | +47.4 |

## 通用榜单（防退化检查）
| 榜单 | Base | +SFT | Δ | 判定 |
|---|---|---|---|---|
| OCRBench (子集) | 82.0 | 81.5 | -0.5 | ✅ 可接受 |
| MMBench-CN (子集) | 76.4 | 75.9 | -0.5 | ✅ 可接受 |
| POPE | 87.1 | 88.3 | +1.2 | ✅ |

> 通用榜单下降 <2pt 视为正常（replay 数据起作用了）；
> 下降 >5pt 说明灾难性遗忘，需要加大通用数据配比。

## 失败模式 Top 5
1. 深色商品的色差判断（32 例）
2. 多图对比时只看了第一张（19 例）
3. 尺码表 OCR 数字读错（14 例）
4. 用户情绪激烈时仍用模板话术（11 例）
5. 把「轻微」和「严重」瑕疵混淆（9 例）

## 结论与下一步
- 拒答能力提升最大 → 说明拒答数据有效
- 色差问题未改善 → 需补深色商品的标注数据
- 下一步：补 3 类数据（深色商品 ×200、多图对比 ×150、瑕疵分级 ×200）
```

**这份报告就是 Day 24 的产出**。注意最后两节——**错误分析比数字更有价值**。

### 评测集版本管理

评测集要**冻结版本**，不能一边测一边改。规范：

```
data/eval/
├── cx_eval_v1.jsonl      # 冻结，不可修改
├── cx_eval_v2.jsonl      # 新增样本，v1 保留以便对比
└── LABELING_GUIDE.md     # 标注手册，随版本更新
```

改评测集等于换尺子，会导致历史数据不可比。新增样本一定开新版本。
