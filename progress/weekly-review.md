# 周复盘

> 每周第 7 天做。**不复盘的一周，等于没有这一周。**
>
> 复盘不是写感想，是回答四个问题：
> 1. **里程碑达成了吗？**（对照 `progress-tracker.md` 的判定标准，不要用「差不多」）
> 2. **这周最大的认知更新是什么？**（改变了你哪个旧想法）
> 3. **哪里浪费了时间？**（具体到哪一天、哪件事）
> 4. **下周要改什么？**（一个具体的、可执行的动作，不是「更努力」）
>
> ------------------------------------------------------------------------
> ⚠️ 每个模板里的「本周特有检查项」很重要。那是这一周最容易骗过自己的地方 ——
> 比如 W2 要检查图像级泄漏，W4 要检查有没有只报好消息的指标。
> 这些检查不做，你会在第 8 周发现结论站不住。
> ------------------------------------------------------------------------

**1. 三条曲线体检**

看 `reports/training_curves.png`，逐条回答：

- [ ] **train loss**：在降吗？从 __ 降到 __
- [ ] **eval loss**：和 train loss 的距离在扩大吗？

- [ ] **grad norm**：有没有尖刺？

## Week 5 · 对齐 + 服务

**里程碑 M5**：DPO 版本 + 可被外部调用的推理 API —— `[ ] 达成 / [ ] 未达成`

```
完成 __ / 6 天        GPU 用时 __ 小时 (¥__)
```

**1. ⚠️ 本周特有检查项**

- [ ] **DPO 的 rewards/accuracies 在涨，但 eval 没变差吗？**
      如果 accuracies 冲到 1.0 而 eval 掉分 → 过拟合偏好数据。
      解法：epoch 降到 1、beta 调大（比如 0.3）。
- [ ] **有没有做「DPO 前后」的完整评测？** 只跑新模型不跑基线的话，
      你无法回答「DPO 值不值」。
- [ ] **量化只做了 LLM 主干，没动视觉塔吧？**
      视觉塔对量化非常敏感，一起量化会导致「看错东西」而语言部分看起来正常 ——
      这种 bug 最难查。
- [ ] **API 有没有并发/超时/降级？** 打一次 `/health`，
      再模拟一次模型服务挂掉，看有没有返回兜底话术而不是 500。

## Week 7 · 产品化

**里程碑 M7**：Shopify 测试店能装、能用、能计费 —— `[ ] 达成 / [ ] 未达成`

```
完成 __ / 6 天        GPU 用时 __ 小时 (¥__)        公网地址: ______
```

**1. ⚠️ 本周特有检查项（这里全是安全坑）**

- [ ] **HMAC 校验：两个测试都过了吗？**
      OAuth 的（先剔除 hmac 参数、再按 key 排序）和
      Webhook 的（**base64 不是 hex**）是两个不同的东西，都测过了吗？
- [ ] **SSRF 防护：`validate_shop` 拦住了 `evil.com` 之类的输入吗？**
      这个不测，你的服务器会被人拿来探测内网。
- [ ] **Webhook 幂等：同一个事件投递 3 次，业务只执行 1 次吗？**
      Shopify 会重试，这是必测项。
- [ ] **Webhook 响应时间 < 5 秒吗？** 超时 Shopify 就重试，
      然后你会收到重复事件 —— 和第 3 条是同一个问题的两面。
- [ ] **计费幂等 + 上限：** usage 重复上报会不会重复扣？超上限会拒绝吗？
- [ ] **GDPR 三个 webhook 都实现了吗？** （`customers/redact`、`shop/redact`、
      `customers/data_request`）没有的话审核过不了。
